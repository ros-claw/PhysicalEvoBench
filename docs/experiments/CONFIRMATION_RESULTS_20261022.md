# 自进化验证：三种子前瞻性对照实验

**按预先登记规则得到的结论：NOT_CONFIRMED。** 本实验检验冻结控制器外部动作增益的反馈搜索，不能等同于权重学习、技能发明或通用自进化。

方案、代码及判定标准在任何新物理 episode 前提交；旧版测试数据未计入。3 个新种子、72 个不同留出条件、528 个真实 PhysX episode；测试每个条件运行四组。测试顺序采用随机平衡轮换，候选只见训练反馈，验证后冻结技能。

## 留出结果

| 组别 | 成功 / 72 | 成功率 | 关节越限采样次数 |
| --- | --- | --- | --- |
| 原策略 | 13 / 72 | 18.06% | 151 |
| 原策略重放 | 17 / 72 | 23.61% | 191 |
| 反馈搜索 | 13 / 72 | 18.06% | 183 |
| 同预算随机搜索 | 14 / 72 | 19.44% | 210 |

**三个种子中反馈与随机搜索均回滚，四组最终使用同一个原策略技能哈希。表中差异是相同技能的不同物理执行，不能解释为算法改善或退化。**

关节计数是每一步每个关节超出硬限位 0.001 坐标单位的采样数，既不是事故数，也不是完整安全证明；碰撞未测量。

## 预先登记的统计比较

差值为反馈搜索减对照。配对区间使用按种子分层、条件内配对 bootstrap 10,000 次；精确单侧二项检验只使用配对胜负，三次比较进行 Holm 校正。

| 对照 | 胜 / 负 | 成功率差（百分点） | 条件 bootstrap 95% 区间 | 原始 p | Holm p |
| --- | --- | --- | --- | --- | --- |
| 原策略 | 0 / 0 | +0.00 | [+0.00, +0.00] | 1 | 1 |
| 原策略重放 | 0 / 4 | -5.56 | [-11.11, -1.39] | 1 | 1 |
| 同预算随机搜索 | 1 / 2 | -1.39 | [-6.94, +2.78] | 0.875 | 1 |

原策略比较的 [0, 0] 区间来自 72 对观测成功标记完全相同导致的退化 bootstrap，不是总体等价或零波动的证明。

这些区间和 p 值以本次三份训练结果为条件；只有三个学习种子，不足以精确估计学习算法跨种子的总体泛化。未确认也不等于证明所有自进化方法无效，亦不等于确认效果为零。

随机搜索使用随机候选，并以同样的训练分数选择最佳候选；这里检验的是反馈指导候选生成相对随机候选的额外价值。

统计方法参考：[SciPy 精确二项检验](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binomtest.html)。

## 可复核证据与适用范围

独立审计 `PASS`：逐项核对 528 个 episode 的官方分数、原始动作及增益、关节计数、质量读回、配对初始状态、训练反馈、选择、验证 gate、预算、冻结技能和跨种子隔离。审计是本地证据一致性检查，不是对恶意实验者的安全隔离。

一次环境构建因上游按秒命名的 HDF5 文件锁冲突而失败，未执行任何 episode；同一预登记种子、条件及算法重试成功。原始失败日志和重试返回码均保留，不计作机器人失败，也不计入正式分数。

公共证据路径：`docs/evidence/confirmation-20261022-001/`。每种子的压缩包保留完整动作/状态轨迹、官方结果和控制台；`SHA256SUMS` 提供校验。解压三个包到同一目录，连同 study JSON 文件，可用 `uv run python -m physicalevobench.evaluation.confirmation_audit --study-dir <目录>` 重新审计。

技能仍为原始 NVIDIA 状态输入控制器加一个增益标量，质量范围仅 0.8–3.2 kg。完整预登记见 [实验计划](CONFIRMATION_PREREGISTRATION.md)。更宽的参数空间、权重更新或新任务需要新方案、新预算和新留出集；不能据此测试结果继续挑选参数，再把这些条件当作未见测试。

要建立更强的自适应证据，须保留实际更新，跨更多独立学习种子复现收益，并战胜同预算随机搜索及身份重放对照。本轮所有结果按预先登记的规则报告，没有追加试验、挑选种子或改写成功条件。

## 本轮判断与下一步

本轮结果没有支持当前标量增益搜索实现有效自进化。训练中出现的局部收益未形成通过验证并保留的更新；继续重放相同留出集不能弥补这一点。要让下一轮有机会提供正面证据，首先需要在训练和独立验证中产生可保留的策略改变。

可检验的下一步假设是扩大可学习技能空间，例如在训练条件中优化抓取/抬升阶段的控制参数，或实际训练策略权重，并向更新器提供经过白名单过滤的训练轨迹诊断；这些方法尚未在本轮实现或验证。新方案应先做训练侧探索和功效估计，再登记更多学习种子与全新留出条件，继续保留随机搜索、身份重放和安全对照。不能承诺换一种方法必然成功。

## 执行版本与工程修正

本轮三次物理执行的源码来自提交 `8135a2675c30f6f87e729cedd93f4403047f04e8`；三个运行保存的 Python 文件 SHA256 完全一致。监督命令为 `uv run python scripts/run_confirmation.py --output runs/confirmation-20261022-001 --gpus 0 1 2`。第三个种子的零 episode 启动失败在同一条件下重试；两次进程返回码分别保留。

实验完成后，工程代码增加每个 run 独立的 recorder 目录及固定目录内文件名，避免上游按秒命名导致并发冲突。这项记录路径修正未用于生成本轮分数；后续独立审计和报告工具的修正也没有改变预登记的统计规则。
